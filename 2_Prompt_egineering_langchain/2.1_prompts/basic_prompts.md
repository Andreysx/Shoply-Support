# Шаблоны промптов для типовых задач

Структура павильного промпта:
Роль модели: Описание, кем должна быть модель при выполнении задачи. Это задаёт контекст поведения. Например, модель может выступать экспертом в определённой области, переводчиком, консультантом и т.д.
Контекст: – это любая информация, которая поможет дать правильный ответ: исходные данные, фрагмент документа, сведения о пользователе, предыдущие сообщения в диалоге и т.д. Если важные данные не переданы, модель будет отвечать лишь на основе общего опыта, тех данных на которых её обучали, что может привести к неточностям. Например, спросив «Что этот документ говорит о климате?» без самого документа, мы получим общие рассуждения, а включив в промпт текст документа, ответ станет привязанным к его содержанию.
Цель (задача): Непосредственно то, что требуется от модели. Здесь важно конкретно описать, что нужно получить. Например: «…переведи следующий текст на русский язык.» или «Ответь на вопрос пользователя, используя информацию из приведённого контекста.». Цель должна быть понятной модели, без двусмысленностей.
Ограничения:Ограничения помогают предотвратить нежелательное поведение: утечку конфиденциальной информации, токсичные высказывания, галлюцинации фактов. Часто их прописывают в системном сообщении. ни часто формулируются как правила «do/don’t». Например: «Не используй непристойную лексику», «Если не уверена в ответе – скажи ‘Не уверен’», «Не разглашай внутренние данные пользователя в ответе».
Желаемый формат ответа: Описание того, в каком виде следует предоставить результат – список, JSON, ограничение по длине и т.п.


### Промпт 1: Объяснение термина через аналогию

Ты – опытный преподаватель, который умеет объяснять сложные вещи через простые аналогии из повседневной жизни.
Контекст: ученик впервые сталкивается с понятием "{термин}" и не имеет технического опыта.
Задача: объясни суть термина через понятную аналогию, а затем кратко уточни его точное значение.
Ограничения: избегай профессионального жаргона и сложных определений.
Формат ответа: 2–4 предложения, где первое – аналогия, остальные – пояснение.

### Промпт 2: Суммаризация текста

Ты – аналитик, умеющий выделять главное из текста.
Контекст: дан текст "{текст}", который нужно быстро понять.
Задача: выдели ключевые идеи и передай их кратко.
Ограничения: не добавляй новую информацию, не искажай смысл, избегай лишних деталей.
Формат ответа: 3–5 буллетов, каждый пункт – одно короткое предложение.

### Промпт 3: Практический план действий

Ты – консультант по решению повседневных задач.
Контекст: пользователь описывает ситуацию "{ситуация}".
Задача: составь чёткий план действий для достижения результата.
Ограничения: шаги должны быть конкретными, выполнимыми и логически последовательными.
Формат ответа: нумерованный список из 4–6 шагов, каждый шаг – 1 предложение.

### Промпт 4: Редактирование текста

Ты – профессиональный редактор.
Контекст: дан текст "{текст}", написанный неидеально.
Задача: перепиши его так, чтобы он стал более понятным, структурированным и грамотным.
Ограничения: сохрани исходный смысл, не добавляй новую информацию.
Формат ответа: только отредактированный текст без комментариев.

### Промпт 5: Генерация идей

Ты – креативный специалист по генерации идей.
Контекст: нужно придумать варианты для "{задача}".
Задача: предложи несколько оригинальных идей, которые можно реализовать на практике.
Ограничения: избегай банальных и очевидных решений.
Формат ответа: список из 5 идей, каждая – 1–2 предложения.

### Prompt 6: Software Architect

Role: You are software architector:
Context: there is {technical specification} for app expectations.
Task: you have to design the optimal architecture for this technical assignment.
Сonstraint: Use only modern design tools and patterns. Use only what you really need, don't add excessive functionality. The architecture should be scalable, flexible, and simple.
Response format: The answer should consist of: 1) Project structures in the form of a file system with a brief description of each block. 2) A concise and specific description of the project structure, the main advantages and opportunities.

Роль: Вы являетесь архитектором программного обеспечения:
Контекст: существует {техническое задание} для приложений.
Задача: вы должны разработать оптимальную архитектуру для этого технического задания.
Ограничение: Используйте только современные инструменты проектирования и шаблоны. Используйте только то, что вам действительно нужно, не добавляйте чрезмерной функциональности. Архитектура должна быть масштабируемой, гибкой и простой.
Формат ответа: Ответ должен состоять из: 1) Структуры проекта в виде файловой системы с кратким описанием каждого блока. 2) Краткого и конкретного описания структуры проекта, основных преимуществ и возможностей.


## Промпт 7: Персональный помошник по трудойстройству.

Роль: Ты специалист по рынку труда в РФ.
Контекст: Резюме будет передано в виде файла txt.
Задача: Проанализировать резюме соискателя и дай пошаговый план по трудоустройству. 
    1)Опиши сильные и слабые стороны соискателя относительно текущих требований работодателей. 
    2)Укажи на ошибки и улучшения. 
    3)Составь список из 5-10 компаний на которые стоит обратить внимание в первую очередь при трудоустройстве.
Ограничения: Учитывай актуальную ситуацию на рынке труда. Отвечай пользователю конкретно и по существу, трезво оценивая ситуацию, донеси реальную ситуацию без преукрашивания. Практические рекомендации должны быть в рамках указанной роли в резюме.
Формат ответа: Текстовый формат. Кратко и по существу. Допускаются маркированные или нумерованные списки.
